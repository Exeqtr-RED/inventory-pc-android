# Инвентаризация ПК — Android (Kotlin + Jetpack Compose)

Офлайн-приложение для инвентаризации компьютерной техники и комплектующих по QR-кодам.
Список позиций хранится локально в Room, интернет не требуется. XLSX читается и пишется
собственным парсером Open XML (только java.util.zip + XmlPullParser), внешние табличные
библиотеки (Apache POI и т. п.) не используются.

## Возможности
- Список позиций с вкладками-категориями («Все» + категории из данных, формат «Категория найдено/всего»);
- Сканирование QR-кодов (CameraX + ML Kit): найденная позиция подсвечивается зелёным,
  отмечается «в наличии» с временем проверки; тот же код игнорируется 1,5 секунды;
- Ручной ввод инв. № на экране сканера; фонарик; вибрация при находке;
- Статусы: «не проверено» (белая), «найдено» (зелёная), «отсутствует» (красная);
  чекбокс, кнопка «Нет на месте» (⊗), редактирование и удаление с подтверждением;
- Импорт из .xlsx: колонки распознаются по заголовкам, выбор «Заменить список» / «Добавить к списку»;
- Экспорт Excel-отчёта (2 листа: «Отчёт» и «Статистика») через системное «Поделиться»;
- QR-наклейки: предпросмотр сеткой 2 колонки + PDF A4 (3×7 = 21 наклейка на лист, ZXing);
- Новая инвентаризация — сброс статусов с сохранением списка.

## Технологии и версии
- Kotlin 2.0.20, Jetpack Compose (BOM 2024.09.03, Material 3), плагин `org.jetbrains.kotlin.plugin.compose`
- AGP 8.5.2, Gradle 8.9, JDK 17
- Room 2.6.1 + KSP; Navigation Compose 2.8.0; Lifecycle 2.8.6
- CameraX 1.3.4 (core, camera2, lifecycle, view)
- ML Kit Barcode Scanning 17.3.0 (распознавание QR)
- ZXing core 3.5.3 (генерация QR для наклеек и PDF)
- compileSdk 35, minSdk 26, targetSdk 35

## Сборка
1. Установите Android Studio (Hedgehog или новее) — в комплекте JDK 17 и Android SDK.
2. В SDK Manager установите платформу Android 15 (API 35) — `compileSdk = 35`.
3. File → Open → выберите папку `inventory-android`.
4. Дождитесь Gradle Sync (зависимости скачаются из google() и mavenCentral().
   Gradle wrapper включён в проект — Studio ничего дополнительно создавать не будет).
5. Build → Build APK(s). Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

Сборка из консоли: `./gradlew assembleDebug`.

### Автосборка на GitHub (без Android Studio)
В проекте есть workflow `.github/workflows/android.yml`: при каждом push в `main`/`master`
GitHub сам собирает **Debug** и **Release** APK (release подписан debug-ключом, поэтому
устанавливается без вашего keystore).

1. Создайте репозиторий на github.com и загрузите в него содержимое папки `inventory-android`.
2. Откройте вкладку **Actions** и дождитесь зелёной галочки (первая сборка ~7–10 минут,
   далее быстрее за счёт кэша Gradle).
3. Внизу страницы сборки — раздел **Artifacts** → скачайте `APK-Инвентаризация-ПК`.
4. Чтобы выпустить «релиз»: сделайте тег `v1.0` (Releases → Draft a new release →
   выберите тег) — APK автоматически прикрепится к релизу и будет доступен по прямой ссылке.

## Как пользоваться
1. **Наполните список.**
   - Меню (⋮) → «Импорт Excel» → выберите .xlsx (формат ниже). После успешного чтения
     программа предложит «Заменить список» или «Добавить к списку».
   - Или добавляйте позиции вручную кнопкой «Добавить» (инв. № и название обязательны,
     дубли инв. № запрещены — ошибка показывается прямо в диалоге).
2. **Проведите инвентаризацию.**
   - Кнопка «Сканировать QR» внизу → наведите камеру на QR-код с инвентарным номером.
     Содержимое QR должно совпадать с колонкой «Инв. №».
   - Найдено: вибрация + зелёная карточка «✓ Найдено: …». Уже отмечено: серая карточка.
     Не найдено: красная карточка «Код не найден» с кнопкой «Добавить позицию»
     (инв. № подставится из кода).
   - Фонарик — иконка вспышки в верхней панели сканера. Ручной ввод — поле внизу сканера.
3. **Работа со списком.** Чекбокс — «в наличии»; крестик (⊗) — «нет на месте»
   (виден у непроверенных); карандаш — редактирование; корзина — удаление с подтверждением.
4. **Наклейки.** Меню (⋮) → «QR-наклейки» → предпросмотр; «Сохранить PDF» формирует
   `naklejki.pdf` (A4, поля 30 pt, 3 колонки × 7 строк) и открывает «Поделиться» —
   можно распечатать на обычном принтере и наклеить на технику.
5. **Отчёт.** Иконка «Поделиться» в верхней панели списка: формирует
   `otchet_ГГГГ-ММ-ДД_ЧЧ-мм.xlsx` (лист «Отчёт» — все позиции со статусами и временем
   проверки; лист «Статистика» — итоги, готовность в % и разбивка по категориям)
   и открывает системное «Поделиться». Данные хранятся в кэше приложения и раздаются
   через FileProvider.
6. **Новая инвентаризация.** Меню (⋮) → «Новая инвентаризация» → «Статусы будут сброшены»
   (список остаётся, отметки обнуляются).

## Формат Excel-файла для импорта (.xlsx)
Первая непустая строка — заголовки. Колонки распознаются по ключевым словам в заголовках
(без учёта регистра, проверяется вхождение подстроки):

| Колонка     | Ключевые слова в заголовке       | Обязательность              |
|-------------|----------------------------------|-----------------------------|
| Категория   | «категор»                        | нет (по умолчанию «Прочее») |
| Инв. №      | «инв», «номер»                   | да (инв. № или название)    |
| Название    | «назван», «наименован», «модель» | да (инв. № или название)    |
| Описание    | «описан», «комплект», «конфиг»   | нет                         |

- Читается только первый лист книги; поддерживаются sharedStrings, rich text и inline-строки.
- Если ни один заголовок не распознан — используется порядок по умолчанию:
  Категория, Инв. №, Название, Описание.
- Строки без названия и без инв. № пропускаются.

## Структура проекта
```
app/src/main/java/ru/pcinventory/app/
  MainActivity.kt            — единственная Activity, NavHost (list / scan / stickers)
  InventoryViewModel.kt      — вся бизнес-логика: сканирование, CRUD, импорт/экспорт, PDF
  data/Item.kt               — сущность Room (позиция инвентаризации)
  data/ItemDao.kt            — DAO (Flow-список, поиск по инв. №, вставка/обновление/сброс)
  data/InventoryDatabase.kt  — база Room (синглтон, inventory.db)
  data/Xlsx.kt               — минимальный XLSX-писатель/читатель без внешних библиотек
  data/ReportBuilder.kt      — отчёт (2 листа) и шаблон для импорта
  ui/theme/Theme.kt          — зелёная светлая тема Material 3
  ui/screens/ListScreen.kt   — список, вкладки, диалоги (в т. ч. общий ItemDialog)
  ui/screens/ScanScreen.kt   — сканер QR (CameraX + ML Kit)
  ui/screens/StickersScreen.kt — QR-наклейки и PDF
```

## Известные ограничения
- Для сканирования требуется разрешение камеры (единственное разрешение приложения);
  без него доступен только ручной ввод инв. №.
- На эмуляторе камера может отсутствовать — пользуйтесь ручным вводом.
- Импорт/экспорт — только .xlsx (Open XML); старый .xls (BIFF) не поддерживается.
- **Инв. № в Excel лучше хранить текстовым форматом ячейки**: если колонка числовая,
  Excel может отобразить «0001» как «1», и QR-код не совпадёт с инв. №.
- QR-наклейки содержат только инв. № — содержимое кода и колонка «Инв. №» должны совпадать
  символ в символ (после обрезки пробелов).
