# Исправления APK — что было не так и как обновить репозиторий

## Почему сборка падала

GitHub Actions доходил до шага компиляции Kotlin (`compileDebugKotlin`) и падал с
`CompilationErrorException`. Причина найдена: в репозитории лежала **старая версия файла
`ScanScreen.kt`**.

В этой старой версии:

- тип результата указывался как `InventoryViewModel.ScanResult`, хотя `ScanResult`
  объявлен **отдельно** (top-level enum в файле `InventoryViewModel.kt`), а не внутри
  класса `InventoryViewModel` → компилятор не может найти такое имя
  (`unresolved reference: ScanResult`);
- отсутствовал `import ru.pcinventory.app.ScanResult`, без которого короткое имя
  `ScanResult.FOUND` / `ScanResult.ALREADY` / `ScanResult.NOT_FOUND` не resolves.

Заодно перепроверен весь остальной код и конфигурация — ошибок больше нет:

| Файл | Статус |
|---|---|
| `app/src/main/java/ru/pcinventory/app/ui/screens/ScanScreen.kt` | **исправлен** (главная правка): добавлен `import ru.pcinventory.app.ScanResult`, тип результата — короткое имя `ScanResult` вместо несуществующего `InventoryViewModel.ScanResult` |
| `.github/workflows/android.yml` | включён в пакет, проверен: список веток `branches: [main, master]`, шаги и артефакты корректны |
| `app/build.gradle.kts` | включён без изменений: release-APK подписывается debug-ключом, чтобы ставился без своего keystore |

Остальные файлы не менялись, но включены в пакет полностью — чтобы можно было залить всё
одним действием и гарантированно заменить все старые версии файлов в репозитории.

## Как обновить репозиторий — способ 1 (рекомендуется, одна загрузка)

1. Распакуйте архив `Исправления_APK.zip`.
2. Откройте https://github.com/Exeqtr-RED/inventory-pc-android
3. Нажмите **Add file → Upload files**.
4. Перетащите в окно **всё содержимое распакованной папки** (папки `.github`, `app`,
   `gradle` и файлы `build.gradle.kts`, `gradlew`, `gradlew.bat`, `settings.gradle.kts`,
   `gradle.properties`, `.gitignore`, `README.md`).
   GitHub сам перезапишет файлы с теми же именами.
5. Внизу введите текст коммита, например `Исправления APK`, и нажмите **Commit changes**.
6. Автосборка запустится сама (вкладка **Actions**). Ждите зелёную галочку (~3–5 минут).

Затем удалите ненужный служебный файл-шаблон, если он ещё есть:
откройте `.github/workflows/blank.yml` → значок **корзины** справа сверху → Commit changes.
(Он ничего не ломает, просто создаёт лишние запуски «Hello world».)

## Как обновить — способ 2 (минимальный, один файл)

Если не хотите перезаливать всё, достаточно заменить один файл:

1. Откройте редактор:
   https://github.com/Exeqtr-RED/inventory-pc-android/edit/main/app/src/main/java/ru/pcinventory/app/ui/screens/ScanScreen.kt
2. Выделите всё (Ctrl+A) и удалите, вставьте **полное содержимое** файла
   `app/src/main/java/ru/pcinventory/app/ui/screens/ScanScreen.kt` из архива.
3. **Commit changes** (Commit directly to the main branch).

## Где взять готовый APK

1. Откройте вкладку **Actions** в репозитории → самый свежий запуск «Сборка Android APK».
2. Внизу страницы запуска в блоке **Artifacts** скачайте **APK-Инвентаризация-ПК**.
3. Внутри архива два файла:
   - `app-debug.apk` — отладочная сборка;
   - `app-release.apk` — релизная сборка (рекомендуется, подписана и устанавливается как
     обычное приложение).
4. Скачанный артефакт — это ZIP: распакуйте на телефоне/ПК, файл `.apk` переносите на
   телефон и устанавливайте (разрешите установку из неизвестных источников).

## Как выложить APK в Releases (необязательно, но удобно)

Ссылка на артефакт живёт 90 дней и требует входа в GitHub. Постоянная ссылка — через
Release: создайте тег, например

```
https://github.com/Exeqtr-RED/inventory-pc-android/releases/new
```

- В поле «Choose a tag» введите `v1.0` и нажмите «Create new tag: v1.0 on publish».
- Нажмите **Publish release**.

Workflow сам соберёт APK и прикрепит `app-debug.apk` и `app-release.apk` к этому релизу —
их сможет скачать кто угодно без входа в GitHub.
